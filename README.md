# VK Bot Guard

Модератор и статистический бот для двух VK-бесед. Накопленная SQLite-база сохраняется при обновлениях.

## Беседы и правила

- `MODERATION_CHAT_PEER_ID` (обычно `2000000001`): одно сообщение в час; второе сообщение, запрещённая лексика, ссылки, стикеры, музыка, голосовые и видео удаляются с ограничением на один час. Для ссылок бот сообщает «Ссылки здесь запрещены». В запрещённую лексику входят «без предоплат», «расход», «коммерческой основе» и «деньги». Уведомление о муте с именем пользователя удаляется через **один час после отправки**.
- `CHAT_PEER_ID` (обычно `2000000002`): статистика, профиль, репутация, Герои дня/недели/месяца/года и админский бан-лист. Почасового лимита нет. Запрещённая лексика строгого чата здесь не применяется. `@all`, банковские карты и телефоны удаляются с мутом на час. Причина для `@all` удаляется через минуту, остальные причины — через десять минут.
- `ADMIN_IDS`: освобождение от автоматической модерации; все обычные команды остаются доступны. `/stat` имеет отдельный список разрешённых аккаунтов.
- Отдельный legacy blocklist-чат задаётся через `BLOCKLIST_CHAT_PEER_ID` и `BLOCKED_USER_IDS`; бан-лист социальной беседы хранится в SQLite.

Модерация проверяет прямое содержимое и вложенные пересланные сообщения. Цитата в `reply_message` не является новым нарушением автора ответа.

Слова и фразы сравниваются целиком с учётом регистра, пробелов и `ё/е`. `мп` не совпадает с «компания» или «температура». Карты проверяются по Luhn.

## Команды

```text
/menu
/profile
/profile @kenaya
/profile @id123

/токсик + @kenaya
/интеллект - @id123

/rep @kenaya
/rep + @kenaya
/rep - @id123

/мут + @username
/неделя
/месяц
/год
/stat
```

- `/profile`: профиль содержит репутацию, ранг по общему числу сообщений за всё время, количество назначений Героем дня/недели/месяца/года и даты последних назначений, сообщения за сегодня и последние 7 дней, личный рекорд сообщений за день и ненулевые характеристики. Обычный участник может открыть свой профиль 2 раза и чужие профили 2 раза за московские сутки; Дон — по 5 раз своего и чужих; администратор — без ограничений. При исчерпании квоты команда удаляется без ответа. При переходе на новый ранг бот объявляет об этом в социальной беседе.
- Свадьбы в `CHAT_PEER_ID`: `/свадьба + @username` отправляет предложение другому Don-участнику. Инициатор и адресат должны иметь активный Don, быть в беседе, не быть в ЧС и не состоять в паре; `/да @username` может отправить только адресат, и на момент согласия оба снова проверяются на Don. Предложение действует 24 часа, а у участника может быть только одно активное предложение (входящее или исходящее); отправитель может отозвать своё через `/отменить свадьбу`. `/супруг` показывает свою пару, `/пары [страница]` — список пар. Профиль участника в паре показывает партнёра и дату свадьбы. `/развод + @username` доступна только с активной Don-подпиской и расторгает брак самого автора команды без подтверждения второго супруга.
- `/подписка + @username` (админы): выдать участнику премиум-подписку на календарный месяц. Повторная выдача продлевает действующую ручную подписку ещё на месяц. Бот объявляет о выдаче/продлении в чате; профиль показывает дату окончания. Привилегии совпадают с Don-премиумом.
- `/характеристика + @username` или `/характеристика - @username`: добавить или снять один балл характеристики. Доступны команды `/интеллект`, `/эрудит`, `/стратег`, `/мудрец`, `/аналитик`, `/гений`, `/загадка`, `/наблюдатель`, `/детектив`, `/википедия`, `/философ`, `/психолог`, `/мемолог`, `/клоун`, `/комик`, `/мем`, `/приколист`, `/шоумен`, `/драматург`, `/комментатор`, `/хаос`, `/провокатор`, `/ураган`, `/пожарный`, `/скрытный`, `/казанова`, `/флиртёр`, `/сердцеед` (также `/серцеед`), `/милашка`, `/ангел`, `/манипулятор`, `/актер` (также `/актёр`), `/дипломат`, `/миротворец`, `/хитрец`, `/альфа`, `/переговорщик`, `/авторитет`, `/бизнесмен`, `/джентльмен` (также `/джентельмен`), `/аристократ`, `/дуэлянт`, `/лизун`, `/дрочун`, `/скуф`, `/токсик`, `/крыса`, `/душнила`, `/спамер`, `/лицемер`, `/скучный`, `/эстет`, `/меломан`, `/киноман`, `/интеллигент`, `/гедонист`, `/романтик`, `/тусовщик`, `/артист`, `/маэстро`. Обычный участник может выдать одну характеристику за неделю. Дон может выдать характеристики не более чем пяти разным участникам за московские сутки; одному и тому же участнику можно выдавать разные характеристики, но ту же характеристику ему — не чаще одного раза за календарную неделю. Администратор не ограничен. Себе характеристику назначить нельзя. После успешного изменения бот пишет короткий комментарий в чат. Повторная выдача той же характеристики и превышение квоты удаляются без ответа. Характеристики с нулевым счётом в профиле скрыты.
- VK Donut: активная подписка от `PREMIUM_DONUT_MIN_AMOUNT_RUB` (по умолчанию 100 ₽/мес.) отображается в профиле как `💎 Дон-премиум: активен`. Отмена продления сохраняет статус до события об окончании оплаченного срока. Ручная премиум-подписка, выданная администратором, действует отдельно и не снимается событиями Donut.
- `/menu`: доступное всем меню с кнопкой профиля и ссылкой на статью-инструкцию.
  Каждый участник может вызвать его один раз за московские календарные сутки; меню удаляется через две минуты. При повторном вызове бот один раз сообщает, что меню уже открывали сегодня.
- `/команды` (админы): бот отправляет короткую кнопку-ссылку на статью со списком команд.
- `/чс @username` (админы): добавить участника в ЧС социальной беседы и удалить его из чата.
- `/чс снять @username` и `/чс список` (админы): снять блокировку или показать список. При повторном приглашении заблокированного пользователя бот удалит его; список хранится в `moderator.db`.
- `/бан + @username`, `/разбан + @username`, `/баны` (админы): добавить пользователя в бан-лист и удалить из чата, снять бан или показать список. Если заблокированного пригласят снова или он появится в беседе, бот удалит его без сообщения. Ответы отправляются на команды администратора.
- `/rep`: без знака повышает репутацию; `+` и `-` явно задают направление. Себе репутацию менять нельзя. Обычный участник может оценить одного другого участника за календарную неделю; Дон — не более трёх разных участников за московские сутки, каждого получателя можно оценить не чаще одного раза за календарную неделю независимо от знака. Администратор не ограничен. Повторные голоса и превышение квоты молча игнорируются.
- `/мут + @username`: действующий Герой дня, недели, месяца или года использует право своего старшего статуса (год > месяц > неделя > день): 1, 4, 8 или 24 часа и один раз за период. Недельные 4 часа бот поддерживает четырьмя последовательными часовыми ограничениями и одним уведомлением. Если автор команды не Герой, он может использовать одноразовое право текущего ранга: от 2 часов для Участника до 10 часов для Легенды; право сгорает после подтверждения VK и не переносится на новый ранг. Ранг не может мутить участника выше себя или действующего Героя. Себя мутить нельзя. Команда пользователя без права удаляется молча.
- При переходе на ранг от «Участника» до «Легенды чата» бот объявляет о новом ранге и сроке доступного мута. Ранги вычисляются по общему числу сообщений; право ранга выдаётся один раз за всё время на конкретном ранге.
- `/неделя`, `/месяц`, `/год` (админы): TOP-5 участников по сообщениям за последние 7, 30 и 365 календарных дней соответственно. Команды остальных участников удаляются без ответа.
- `/легенды`: список всех участников с рангом «Легенда чата» (100 000 и более сообщений), от самого активного к менее активным; доступен всем участникам.
- `/stat`: общая статистика социального чата за текущий день, включая число участников с хотя бы одним сообщением и текущую активность относительно среднего числа сообщений за предыдущие 7 полных дней. Доступна только для `@piterparker34`, `@kenaya`, `@id1122341522`. Результат публикуется в чат. Числовой ID третьего аккаунта проверяется без API. Два коротких имени разрешаются и кешируются на время процесса; при сбое API команда остаётся в очереди на повтор. Для независимости от API задайте **фактические числовые ID этих трёх аккаунтов** через `STAT_ALLOWED_IDS`.

Числовые упоминания проверяются целиком: `@123abc` не превращается в ID 123.

## Статистика и Герой

Время задаётся `CHAT_TIMEZONE` (по умолчанию `Europe/Moscow`).

- В 06:00, 12:00, 18:00 публикуются накопленные показатели текущего дня, число активных участников, активность относительно среднего за предыдущие 7 полных дней и TOP-3.
- В 00:00 назначается Герой дня на следующие сутки по сообщениям за завершившийся день.
- Каждый понедельник в 00:00 назначается Герой недели по сообщениям за предыдущие 7 дней; 1-го числа — Герой месяца по предыдущим 30 дням; 1 января — Герой года по предыдущим 365 дням.
- Статусы действуют до следующего соответствующего рубежа. При совпадении статусов старший статус поглощает младший; муты не суммируются.
- Ночной пост Героя дня включает действующие рекорды чата и рекорд сообщений Героя дня за сутки. Новые максимумы дополнительно отмечаются.
- В понедельник в 12:00 публикуются итоги предыдущей недели с TOP-5.
- Каждый день в 08:00 публикуется утренний пост: дата, прогноз погоды в Волгограде, совет и вопрос из строки Google Таблицы, у которой дата совпадает с сегодняшней. Если совет или вопрос в строке пуст, соответствующая часть сообщения пропускается; при длинной остановке бота пост старше 30 минут не отправляется.
- Каждый день в 12:00 по `CHAT_TIMEZONE` публикуется реклама Don-премиума; если бот опоздал более чем на 30 минут, публикация за этот день пропускается.
- При равенстве числа сообщений побеждает меньший числовой ID.
- Учитываются обычные сообщения людей и их прямые вложения. Команды, нарушения и события входа/выхода не участвуют в активности. Сообщения администраторов учитываются по тем же правилам.

### Утренний пост и Google Таблица

Источник контента: [VK Bot Guard — утренний контент](https://docs.google.com/spreadsheets/d/1us-ZoLGbyNYI-J6HQMHofHCPIdEcUes-Sj3KkKjqLyg/edit). На листе `Утренний контент` используются три колонки: `Дата`, `Совет`, `Вопрос`. Формат даты — `ГГГГ-ММ-ДД`, например `2026-11-14`; одна строка соответствует одному дню. Бот публикует содержимое строки с сегодняшней датой, а если её нет — утренний пост выйдет без совета и вопроса. Бот обновляет локальный JSON-кеш и использует его, если Google временно недоступен.

На листе `Новости проекта` используются две колонки: `Дата и время (дд/мм/гггг чч:мм)` и `Текст новости`. В первой колонке укажите дату и время публикации (например, `14/11/2026 12:30`), во второй — текст сообщения. Время указано по `CHAT_TIMEZONE` (по умолчанию `Europe/Moscow`). Каждая строка — отдельная новость; при сбое Google используется локальный кеш. Бот проверяет лист раз в минуту, публикует новость один раз и пропускает её, если бот запустился более чем через 30 минут после назначенного времени.

Для чтения приватной таблицы настройте Google service account: включите Google Sheets API в проекте Google Cloud, создайте JSON-ключ сервисного аккаунта и поделитесь таблицей с адресом `client_email` из этого JSON с правом **Читатель**. Сохраните ключ на сервере в `/opt/vk_bot_guard/google-service-account.json`, затем добавьте в `.env`:

```text
MORNING_GOOGLE_SHEET_ID=1us-ZoLGbyNYI-J6HQMHofHCPIdEcUes-Sj3KkKjqLyg
GOOGLE_SERVICE_ACCOUNT_FILE=/opt/vk_bot_guard/google-service-account.json
```

Защищайте JSON-ключ и не добавляйте его в GitHub. Прогноз загружается с Open-Meteo; строка сообщения содержит указание источника.
- После перезапуска планировщик догоняет пропущенные события за последние семь дней. Старые промежуточные снимки прошлых дней не восстанавливаются: публикуются окончательные итоги. При первом запуске новой версии подхватываются вчерашний итог/Герой и последний уже наступивший дневной отчёт. Исторические Герои сохраняются без объявления права на мут за уже прошедшие дни.

Муты в новых недельных отчётах считаются **только для социального чата**. Старые агрегаты сохранены, но автоматически распределить их между чатами невозможно: такой информации прежняя схема не хранила.

## Надёжность

Входящее событие сохраняется в `inbox`. Его локальные изменения (голос, cooldown, статистика, очередь действий) и отметка обработки фиксируются одной транзакцией. Ошибка откатывает изменения; событие повторяется после задержки.

Действия VK сохраняются в `outbox`. Временные ошибки повторяются с увеличением задержки до пяти минут, максимум 12 попыток. Ошибки доступа и параметров переходят в `failed`, задания для исключённых из конфигурации чатов и уведомления старше шести часов — в `cancelled`. Эти записи сохраняются для диагностики; автоматически в другую беседу они не перенаправляются.

- Отправки используют постоянный ненулевой `random_id` и параметр `peer_ids` для полного ответа. Успех проверяется для нужного адресата, включая вложенную ошибку. Сохраняется `conversation_message_id` даже при `message_id=0`. Ответ без обоих идентификаторов считается неоднозначным: задание блокируется для ручной проверки, повторная отправка автоматически не выполняется.
- Локальный мут и его статистика подтверждаются только после успешного ответа VK. У очереди есть отдельное ожидающее ограничение, чтобы не создавать повторные запросы.
- Повтор мута использует оставшееся время до исходного окончания и не запускает новый полный час. Если срок прошёл, ограничение не выдаётся.
- Сообщение о наказании отправляется после подтверждения мута и удаления исходного сообщения.
- Временные сообщения удаляются через сохраняемую очередь; перезапуск не теряет удаление. Для номера внутри беседы используются `peer_id` и `cmids`; старые задания с глобальным ID тоже поддерживаются. Проверяются подтверждения всех запрошенных сообщений и ошибки внутри списочного ответа. Отсутствующая или ошибочная зависимость блокирует уведомление об удалении.
- Истечение мута не вызывает принудительный `rw`: ограничение с `for` истекает в VK, а бот не снимает чужие наказания.
- Второй процесс бота в той же папке не запускается благодаря блокировке ОС.

Гарантии относятся к событиям, уже полученным и сохранённым ботом. События за время полного отключения могут отсутствовать в Long Poll; исторические сообщения из VK автоматически не загружаются. Для внешнего API нет общей транзакции с SQLite: при неоднозначном ответе действие повторяется, отправки защищаются `random_id`, а муты — исходным сроком. Работа требует токена сообщества, включённых событий Long Poll и прав администратора беседы.

## Сохранность данных

Миграции последовательные, текущая схема — **v18**. Перед миграцией существующей базы создаётся резервная копия через SQLite backup API, включая зафиксированные данные из WAL. Миграция транзакционная. Пользовательские таблицы не удаляются.

Новые таблицы: `inbox`, `outbox`, `chat_mute_stats`, `cleanup_tasks`, `chat_blacklist`, `chat_stat_records`, `premium_subscriptions`, `processed_donut_events`, `user_characteristics`, `characteristic_gives`, `profile_view_usage`, `hero_titles`, `morning_content_history`, `marriages`, `marriage_proposals`. Старая статистика, репутация, история Героев и пользовательские данные сохраняются. Лог ротируется: основной файл до 5 МБ и три резервных файла.

## Запуск и обновление

### VK Donut

Создайте уровень VK Donut за 100 ₽ в месяц. В настройках сообщества откройте **Long Poll API** и включите `donut_subscription_create`, `donut_subscription_prolonged`, `donut_subscription_cancelled` и `donut_subscription_expired`. Оставьте включённым `message_new`, который нужен для работы бота. После этого перезапустите `vk-bot-guard`; отдельный домен, HTTPS и новые секреты в `.env` не нужны. Минимальная сумма задаётся параметром `PREMIUM_DONUT_MIN_AMOUNT_RUB` (по умолчанию 100).

Бот обрабатывает Donut-события в существующем Long Poll-потоке, учитывает каждое один раз по `event_id`, выдаёт премиум после создания/продления подписки от заданной суммы и снимает его после `donut_subscription_expired`. `donut_subscription_cancelled` помечает отмену автопродления, но сохраняет премиум до конца оплаченного срока.

Python 3.12:

```text
pip install -r requirements.txt
```

При первом запуске скопируйте `.env.example` в `.env`, заполните параметры и запустите:

```text
python bot.py
```

На Windows доступен `start.bat`. Для обновления остановите текущий процесс, обновите код в его папке и запустите снова. **Существующие `.env` и `moderator.db` сохраняйте.** Новые очереди и таблицы создаются миграцией автоматически; для Donut достаточно включить нужные события в настройках Long Poll API сообщества.

## Проверки

Для тестов нужны только фиктивные значения конфигурации, рабочий токен не требуется:

```bash
VK_TOKEN=test GROUP_ID=1 CHAT_PEER_ID=2000000002 MODERATION_CHAT_PEER_ID=2000000001 python -m unittest discover -s tests -v
```

В GitHub Actions тестовая конфигурация задаётся явно. Проверяются миграции и backup WAL, команды и разрешения, статистика, дедупликация, откат обработки, повторная доставка, сроки мутов, автоудаление, планировщик и перезапуск. VK заменён имитацией API; эти тесты не подтверждают права или настройки живого сообщества.

Не публикуйте `.env`, токены, базы, очереди и логи.

## Проверка очереди на сервере

```bash
cd /opt/vk_bot_guard
.venv/bin/python scripts/queue_status.py
```

Команда читает базу без изменений, показывает состояния, номера заданий, адресатов и ошибки. Токен и тексты сообщений не выводятся. `done` означает подтверждённую доставку; `pending` — ожидание; `failed` — нужна проверка; `cancelled` — доставка отменена. Новая попытка старого сообщения не создаётся автоматически после смены `.env`. Для проверки актуального доступа отправьте новую `/stat`; не переотправляйте неоднозначные старые уведомления без проверки чата.
