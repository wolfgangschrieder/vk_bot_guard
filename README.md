# VK Bot Guard

Модератор и статистический бот для одной активной VK-беседы.

## Беседы

Бот работает с двумя беседами:

- `2000000001` — строгая модерация;
- `2000000002` — статистика, профиль, репутация и Герой чата.

Остальные беседы игнорируются.

## Чат 2000000001

В строгом чате:

- действует лимит 1 сообщение в час;
- запрещённая лексика включает `мп`, `дорого`, `цена`, `стоимость` и другие заданные правила;
- за запрещённую лексику сообщение удаляется, пользователь получает мут на 1 час, бот пишет `🚫 Проституция здесь запрещена...`;
- стикер удаляется и приводит к муту на 1 час;
- музыка и видео также обрабатываются существующим правилом;
- причина автоматического мута удаляется через 10 минут.

Сообщения администраторов из `ADMIN_IDS` не модерируются.

## Чат 2000000002

В чате статистики:

- за `@all` сообщение удаляется, пользователь получает мут на 1 час;
- бот отправляет `@all -Здесь такие команды запрещены`;
- это сообщение бота удаляется через 1 минуту;
- банковские карты и номера телефонов по-прежнему модерируются;
- обычный лимит 1 сообщения в час здесь не применяется.

Бот публикует текстовую причину. Сообщение с причиной автоматического мута удаляется через 10 минут.

Для номеров банковских карт используется проверка контрольной суммы Luhn, чтобы не реагировать на любой случайный набор цифр.

## Статистика дня

Статистика публикуется в:

- 06:00;
- 12:00;
- 18:00;
- 00:00.

Публикация содержит:

- количество сообщений за день;
- фото;
- видео;
- музыка;
- голосовые сообщения;
- TOP-3 самых активных пользователей;
- количество сообщений каждого пользователя.

В 00:00 публикуется уже завершившийся день.

## Герой чата

В 23:59 бот определяет пользователя с максимальным количеством сообщений за день.

Победитель получает титул:

```text
🦸 Герой чата
```

История королей сохраняется.

В течение следующего календарного дня Герой может использовать:

```text
/мут @id123
```

и выдать пользователю мут на 1 час.

Бот сообщает:

```text
🦸 Герой чата выдал мут пользователю @... на 1 час.
```

## Репутация

Команды:

```text
/profile
/profile @id123

/rep + @id123
/rep - @id123
```

Ограничения:

- команду `/profile` любой пользователь может использовать раз в 3 дня;
- одному пользователю можно дать конкретному участнику только один голос за календарную неделю;
- голос может быть `+1` или `-1`;
- самому себе голосовать нельзя.

Профиль пока показывает только репутацию.

## Муты в статистике

Отдельная история каждого мута не хранится.

В БД сохраняются только агрегированные значения:

- сообщения пользователя за день;
- выданные ему муты за день.

На их основе рассчитываются дневные, недельные и месячные показатели.

## Еженедельная статистика

Каждый понедельник в 12:00 публикуется статистика предыдущей недели (понедельник-воскресенье):

- всего сообщений;
- всего мутов;
- TOP-5 активных пользователей.

В заголовке указывается дата начала недели, например:

```text
#3ноября
```

## Сохранность данных

Рабочая SQLite-база не пересоздаётся при обновлении кода.

Используется таблица `schema_migrations`. Новые версии схемы добавляются последовательными миграциями:

```text
v1 → v2 → v3 → ...
```

Существующие таблицы и статистика не удаляются.

Основные постоянные данные:

- `users` — состояние лимитов и мутов;
- `daily_user_stats` — сообщения и агрегированные муты пользователей по дням;
- `daily_stats` — общие показатели дня;
- `king_history` — история Королей;
- `reputation_votes` — недельные голоса репутации;
- `command_cooldowns` — cooldown команд;
- `bot_messages` — временные сообщения бота для автоудаления;
- `scheduler_state` — защита от повторной публикации событий.

Старые таблицы почасовой статистики могут оставаться в существующей БД как исторические данные, но бот больше их не использует и не публикует.

## Запуск

```text
pip install -r requirements.txt
copy .env.example .env
python bot.py
```

Для Windows можно использовать `start.bat`.

## Тесты

```text
python -m unittest discover -s tests -v
```

## Безопасность

- настоящий `.env` не должен попадать в Git;
- SQLite-база и логи не должны попадать в Git;
- токен VK нельзя публиковать;
- перед изменениями схемы рабочую БД рекомендуется копировать в backup.

## Принцип развития

Код можно обновлять и расширять, но пользовательская история и статистика не должны теряться.

Новые функции добавляются поверх существующих данных через миграции, без `DROP TABLE` и пересоздания рабочей БД.
